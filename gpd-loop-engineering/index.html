What the loop still does not do for you

02

Comprehension debt compounds

Design lessons from building loops

Five things I'd tell myself a year ago.

01

Persistence isn't the frontier; discovery is. Mine are chartered, not yet proven.

02

Knowledge must flow both ways. Human-gated write-back matters more than another loop.

03

Audit the estate, not just the code. Comprehension debt accumulates between projects.

04

Verify the plumbing. A lost sub-agent report can invalidate the loop.

05

Budget caps are stop conditions. Cost per verified result must fall as the loop matures.

Designing for cost / the token meter is always running

A good loop gets cheaper every lap.

01
Remember, don't re-learn

State on disk means short warm-ups — no run pays to rediscover what the last one knew.

02
Point, don't paste

Send references, fetch only what the step needs — the biggest bills are context that was never read.

03
Right-size the model

Small models for routine steps, the big one only where judgment lives.

04
Stop early, stop often

Cheap checks run first; budget caps end a bad lap before it gets expensive.

The test: if cost per verified result does not bend down as the loop matures, redesign the loop — not the metrics.
