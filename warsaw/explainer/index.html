02 / FIRST, WHAT IS IT?

Things.
Connections. Rules.

A list tells you what exists. A graph also tells you how things relate. Graph engineering makes those relationships explicit, then uses them to answer a practical question.

01

A node is a thing.

A place in a game. A piece of code. A review step. Choose what a dot represents before you connect it to anything.

02

An edge is a relationship.

A line might mean “can walk there,” “depends on,” or “contains.” An arrow adds direction. The meaning matters more than the picture.

03

Rules make it useful.

Which connections are valid? What does a route cost? Which checks must finish? Rules turn a map of relationships into a tool for making decisions.

GRAPH ENGINEERING, IN ONE SENTENCE

Model the relationships that matter. Then use them to plan, search, coordinate or validate. This idea works with ordinary code and with AI agents. A graph does not itself make a system intelligent or reliable.

Six graph words, in everyday language
Path
A sequence of connected nodes that you can follow.
Weight / cost
A number on an edge, such as distance, time or effort. Its unit must be defined.
Directed graph
A graph with arrows. A connection from A to B does not automatically allow B to A.
DAG
A directed acyclic graph: arrows have direction, and following them cannot take you back to where you started. Useful for prerequisites.
Tree
A connected graph without cycles. A rooted tree organizes nodes into parents and children, like a scene hierarchy. NIST definition ↗
Cycle
A route that comes back to an earlier node. Useful for feedback, but problematic for circular prerequisites.

A PRACTICAL WAY TO START

Question → model → check.

  1. Name the question. What decision will the graph help make?
  2. Define nodes and edges. State the meaning, direction and any costs.
  3. Apply the relevant rule. Order prerequisites, search a path or join checks.
  4. Test the awkward cases. Missing results, closed links, cycles, stale outputs.
  5. Maintain the model. Recheck connections when the real system changes.

Sometimes a list is enough.

For a few independent reminders, use a list. For a fixed sequence with no branches, a checklist can be clearer. Add graph structure when relationships solve a problem; maintaining nodes, edges and rules also costs work.

What this case study does not prove

It does not establish how much faster or cheaper AI made the project, that every defect was found, or that a successful test predicts every real player’s experience. A review marked “clean” is evidence of that review’s result—not a guarantee.
